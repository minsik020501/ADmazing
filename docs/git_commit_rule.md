# Git Commit Rules

이 프로젝트의 커밋 메시지 작성 규칙입니다. 기존 커밋 히스토리(`feat:`, `fix:`, `chore:` 접두사 사용)를 기준으로 정리했습니다.

## 형식

```
<type>: <subject>

<body (선택)>

<footer (선택)>
```

## Type

| Type       | 설명                                            |
|:-----------|:------------------------------------------------|
| `feat`     | 새로운 기능 추가                                |
| `fix`      | 버그 수정                                       |
| `chore`    | 빌드, 설정, 스크립트 등 코드 로직과 무관한 변경 |
| `refactor` | 기능 변경 없는 코드 구조 개선                   |
| `docs`     | 문서 추가/수정                                  |
| `test`     | 테스트 코드 추가/수정                           |
| `style`    | 포맷팅 등 코드 동작에 영향 없는 변경            |

## Subject 규칙

- 한국어로 작성
- 명령형(imperative mood) 사용: `추가`, `수정`, `업데이트`
- 끝에 마침표를 찍지 않음
- 50자 이내 권장

예시:
```
feat: 한국어 프롬프트 OpenAI 번역 서비스 추가
fix: 이미지 생성 API 타임아웃 시 예외 처리 보완
chore: FastAPI 11000, React 12000 포트 변경
```

## Body

- subject만으로 변경 이유(why)가 충분히 설명되지 않을 때만 작성
- 무엇을 바꿨는지보다 왜 바꿨는지에 집중

## 기타

- 하나의 커밋은 하나의 논리적 변경 단위로 구성 (여러 기능을 한 커밋에 섞지 않음)
- `--no-verify`, `--amend`(재작성이 필요한 경우 제외) 등은 사용하지 않음
